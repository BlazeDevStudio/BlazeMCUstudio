# Inert UART framing lab — v0.4.13

**Status: real source code and target compilation fixture, not physical device validation.**

This increment supplies a bounded, native-testable C++ UART frame parser under `core/firmware/BlazeUartFrame.h` and two genuine Arduino sketches generated by `scripts/export-uart-lab.cjs`.

## Build / samples

Use an existing output parent directory:

```bash
node scripts/export-uart-lab.cjs /path/to/empty-output-root
```

This creates:

- `BlazeUartEsp32Initiator/BlazeUartEsp32Initiator.ino` for `esp32:esp32:esp32`, using `Serial1.begin(9600, SERIAL_8N1, 16, 17)` — GPIO16 RX, GPIO17 TX.
- `BlazeUartEsp8266Responder/BlazeUartEsp8266Responder.ino` for `esp8266:esp8266:generic`, using hardware UART0 `Serial.begin(9600)` — GPIO3 RX, GPIO1 TX.
- Each generated Arduino sketch directory includes an identical local copy of `BlazeUartFrame.h`.

The exporter fails rather than overwriting an existing lab sketch directory. It **does not** modify saved project source, existing workspace `pins`, a configured device's firmware, or automatically flash anything.

The source module declares a deterministic frame layout:

| Field | Bytes |
|---|---:|
| Start marker `0xA5` | 1 |
| Version `0x01` | 1 |
| Kind `0x01` PING or `0x02` PONG | 1 |
| Sequence (uint8, wraps) | 1 |
| Payload length (0–16) | 1 |
| Payload (arbitrary binary, including `0xA5`) | 0–16 |
| CRC-8 polynomial `0x07`, init `0x00` (over version through payload; no start marker) | 1 |

**Maximum 22 bytes**, fixed storage, no heap allocation by the framing module, 250 ms incomplete-frame timeout with unsigned `millis()` wrap. Invalid kinds, versions, lengths, and CRC are rejected. Only an inert PING generates an echo PONG with the same sequence and payload; PONG produces no reply. The ESP32 sample sends a PING at one-second intervals and counts matching one-byte PONG responses in a loop-local-module counter, with no GPIO outputs or serial debug text. The ESP8266 sample listens for and replies to PING. No security or authorization is implied by CRC or sequence numbers.

## CI verification contract

- Execute `tests/native/uart-frame-test.cpp` using genuine C++11 compilation and ASan/UBSan under Linux for known CRC vector, invalid packets, size bounds, payload including marker bytes, incomplete frames, `millis()` rollover, and fuzz/resynchronization cases.
- Generate and compile **both** Arduino sketch sources using pinned ESP8266 core 3.1.2 / ESP32 core 3.0.7 in the existing real-board compilation CI matrix. Preserve previous Blink, AVR and Windows portable app/GUI gates. Archive the compile logs.
- Node tests check safe exporter, exact local header copy, UART configurations, absence of GPIO control in frame codec and a no-overwrite refusal.

## NOT demonstrated / do not wire by inference

Real electrical wiring, GND continuity, actual connector breakout, TX-to-RX crossover, power regulation, UART USB converter/programming contention, level shifting, board variants and voltage/current are **unverified**. The ESP8266 UART0 may be shared with USB programming and debug hardware; while the classic ESP32 UART1 permits mapped RX16/TX17 in this example, carrier/PSRAM restrictions still require external review. Compilation does **not** prove UART transfer, frame latency, electrical safety, data integrity in noise, peer pairing, replay protection, authentication, encryption, or readiness for coin/relay control.

**No flashing, no payment or relay functions, no production signing or release.** The module must remain isolated from financial admission/control paths and is not automatically connected to the workspace planner. A future separate milestone can add user-controlled export of compatible project-specific pair sketches after pin and UART-peripheral ownership validation; real wire acceptance remains NO-GO until independent physical bench evidence.
